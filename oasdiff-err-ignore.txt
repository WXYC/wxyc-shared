# oasdiff error-level ignore list.
#
# Format: one line per suppressed finding, `<method> <path> <message>` exactly as
# oasdiff renders it (extra spaces collapsed), except that the method must be
# written LOWERCASE. oasdiff prints `GET` and matches either case, so an uppercase
# entry does suppress correctly — but
# scripts/__tests__/check-breaking-changes.test.sh requires every live entry to
# match `^(get|post|put|patch|delete) /` and fails on it, and that failure reads
# as a broken whitelist when the suppression is in fact fine. This note lives in
# the header rather than beside an entry because the per-entry version of it was
# pruned along with its entry, and the mistake immediately recurred. A line that
# matches nothing — including a `#` comment — is inert.
#
# Entries here are scoped to a `main`..PR diff, so an entry stops matching the
# moment its change lands on `main`. Prune dead entries when you notice them;
# an entry that outlives its diff suppresses nothing but reads as if it does.
# Prune ENTRIES, never the file: both the CI job and
# scripts/check-breaking-changes.sh pass this path unconditionally, and oasdiff
# exits 121 when it is missing. An entry-free file of comments is the floor.
#
# Entries must reproduce oasdiff's rendered message verbatim (a substring like
# "became nullable" matches nothing), so an oasdiff release that rewords a
# message silently un-matches its entry and turns the job red. If that happens,
# re-run the check locally and paste the new wording; don't assume the
# suppression is still in force because the line is still here.
#
# Every entry needs a written justification. "oasdiff is being annoying" is not
# one — a genuine breaking change gets a contract-version conversation, not a
# line in this file.
#
# Worked example of the pruning rule, kept because the rule reads abstractly
# until you have seen it applied once: the two wxyc-shared#297 suppressions
# (`BulkResolveTrackIdentity.track_position` and `BulkResolveResult.tracks`
# becoming nullable) landed on `main` in api.yaml 1.30.0, stopped appearing in
# any `main`..PR diff, and were pruned.
#
# Deliberately not recorded here: how many entries are currently live. A comment
# claiming a count is wrong the moment someone appends an entry below it, and no
# test can catch that — the checks in
# scripts/__tests__/check-breaking-changes.test.sh skip comment lines by
# construction. Read the entries.

# wxyc-shared#298 — `RotationEntry.album_id` declared a required non-nullable
# integer for a column that carries no NOT NULL. `rotation.album_id` is null on
# every row of the Awaiting Cataloging queue (`GET
# /library/rotation/uncatalogued` is defined as exactly the rows where it is
# null), and both operations returning this schema echo the raw rotation row,
# so a kill against an uncatalogued row already reports the null these entries
# say is impossible. dj-site carries a guard against it in `killRotationEntry`
# whose comment states that the contract contradicts the column.
#
# These are errors rather than the warnings the sibling nullability fixes drew
# (#332, #496): those properties sat inside an `allOf` branch, so oasdiff could
# not rule out a sibling branch still guaranteeing non-null and downgraded.
# `RotationEntry` is a flat object, so the finding is certain. The break is
# real and intended — the contract takes a major (6.0.0 -> 7.0.0), which is the
# signal consumers actually receive. Suppressed here only so the diff can land.
#
# PRUNE AFTER MERGE: diff-scoped, inert the moment this lands on main.
